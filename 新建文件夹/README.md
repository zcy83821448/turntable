# OHM DECK · 唱片机

一个单页的三维唱片机展示页面。**模型来自 `D:\桌面\A\唱片机.blend`**，导出成 glTF 内联进页面；
材质、灯光、后期、界面全部由代码生成，运行时零网络请求。

界面沿用了「档案终端」的样式：页头是机型，右侧是当前档案的正文，底部是控制台。
这台机器被拆成六条档案——整机，加上它的五个零件——读一条零件档案，该零件留在真实材质上、
其余零件退成幽灵，镜头同时切到它自己的机位。

## 打开

直接双击 `index.html` 即可。`dist/app.js` 里已经包含了 three.js、整个模型和全部贴图，
`file://` 下可以正常运行。

> 这一条是设计约束，不是巧合。`GLTFLoader` 用 `fetch` 取模型，而 `file://` 页面发出的 fetch 会被当成
> 跨源请求挡掉。所以模型不是「读一个 .glb」进来的，而是被 esbuild 的 `binary` loader 编成了
> `Uint8Array` 塞进 bundle，再用 `GLTFLoader.parse()` 解 —— 见 `build.mjs` 和 `src/turntable.js`。

## 模型从哪来

几何**不在这个仓库的代码里**，在 Blender 里。`src/turntable.js` 只负责行为。

导出前的整理脚本是 `tools/export-glb.py`（在 Blender 里跑，见文件头的说明）。它做四件事：

1. **给每个物体和每个材质起名字**。原本是 `柱体.007`、`材质.011`，现在是 `ArmTube`、`Brass`。
   这既让人看得懂大纲，也是页面把材质换成自己那套的接口（`MAT_MAP`）。
2. **把 41 个网格归到八个空物体下**，每个空物体的原点就落在它真正绕着转的那根轴上：

   | 节点 | 装什么 | 原点 | 动吗 |
   | --- | --- | --- | --- |
   | `Plinth` | 底座、四只脚、控制区、铰链楔形（17 个） | 台面中心 | 不动 |
   | `Platter` | 转盘、盘沿、中心轴（3 个） | 主轴 | 转 |
   | `Record` | 唱片（1 个） | 主轴 | 转 |
   | `Arm` | 臂管、唱头、平衡锤（9 个） | 轴承 | **摆** |
   | `ArmSwivel` | 万向节、摇臂座（2 个） | 轴承（同一个） | 摆 |
   | `ArmMount` | 底板、轴套（2 个） | 轴承（同一个） | 不动 |
   | `Cover` | 左铰链臂、玻璃、右铰链臂（3 个） | 铰链线 | **翻** |
   | `CoverMount` | 铰链桶身与端盖（4 个） | 铰链线（同一条） | 不动 |

   于是「驱动这台机器」= 在一个节点上写一次 `rotation`，没有几何可以写错。

   **成对的那两组**（`Arm`/`ArmMount`、`Cover`/`CoverMount`）是同一件事：前一个是在动的零件，
   后一个是它绕着转、但焊死在底座上的那个座。页面从不写后一个。

   **`ArmSwivel` 现在和 `Arm` 做的事一样**（都只吃偏航），是上一轮为"抬臂不能加在轴承件上"而拆的。
   竖直位移已经整个取消（见下），所以它眼下是冗余的；留着的唯一理由是如果哪天要把落针改成
   **绕水平轴俯仰**（那才是真实唱臂的动作），轴承件必须不吃那个俯仰——那时它就是现成的。
   想清掉的话，把 `立方体.003`/`柱体.016` 放回 `Arm`、删掉这个组和页面的三处引用即可。

   **共享材质不代表共享运动。** `立方体.003` 最初被归进 `ArmMount`，因为它和底板共用 `材质.019`，
   读起来像同一块铸件——但材质是共享的，运动不是。它落在离转轴 0.417、万向节的高度上，是托着万向节的
   那个摇臂座，跟着唱臂走。**分组要按"它绕哪根轴转"判，不是按"它和谁同色"。**
   移之前核过两件事：它在 Z 上和底板不重叠（0.984 对 0.901），而它绕轴扫掠的半径是 **0.856**，
   够不到任何固定件。（这条理由我第一版写错了：当时写的是"托柱在 −Y 侧、离它 180°"——
   托柱其实**就在唱臂那一侧**。够不到它的是**摇臂座**，够得到它的是臂管，见下条。）

   **有一个件是直接不要的。** `立方体.006`（一个 U 形小支架）不在这 41 个里面：唱臂管是**从它中间穿过**
   的，不是扫过去——管子占 `Y 2.87…−2.61 / Z 1.09…1.42 / X 4.11…4.43`，支架占
   `Y 2.04…2.25 / Z 0.40…1.49 / X 4.00…4.52`，两者在整个行程上都相交，看起来就是长臂在锯一个 U 形座。
   不管它原本打算托住什么，按现在这个摆位它就是立在唱臂的路径上，**页面能移动零件，但没有办法让它们不相交**。
   所以在导出时删掉（`DROP`），在内存里做，`.blend` 不写。

   **唱臂为什么要两组**：一开始整条 `Arm` 是一组，转起来连拧在台面上的底板一起摆。
   底板离轴线有 2.0 单位远，46° 的行程把它扫过大半个画面——而且正好扫在按下播放、
   最该安静的那一下。分成两组之后 `Arm` 在 `ArmMount` 里摆，`ArmMount` 焊在底座上，
   臂管从轴承座中间穿过去，看起来才像一根轴在座里转。分界线怎么定的：把候选的"座"
   单独渲出来看它是不是一座完整的塔、候选的"臂"单独渲出来看它是不是一支完整的臂
   （`armx_*` / `ax_*` 那几张），两边都不缺件才落刀。

   **唱臂不做任何竖直运动，这是量出来的结论。** 页面原本在停转时把整个 `Arm` 组**平移**上抬
   0.36 单位（12.9 mm），当作抬臂。平移不是唱臂的动作——真实的是绕轴承附近的水平轴俯仰，
   前端抬起、平衡锤下沉，**没有任何东西离开托着它的座**。整组平移则必然在安装处撕开一道缝，
   而那道缝在臂、摇臂座和轴之间，于是唱臂在暂停时看起来和底座脱开了，一按播放又正常
   （`armDown` 为 1 时偏移恰好是 0）。
   现在那行不写了，唱臂只摆动。判定用不动的底座当基准测各零件相对高度：取消前臂管相对底座
   在静置/播放两态相差 **0.3225**（= 抬臂量），取消后是 **0.0018**，和摇臂座、万向节一致。
   （中间走过一段弯路：先把万向节和摇臂座单独拆成 `ArmSwivel`，结果是臂被拆成两截，
   上半截还在飘——**问题不在于哪些件该跟着动，而在于那个位移本身就不该存在**。）
3. **统一单位**：底座缩到 10.5 页单位宽，并把**台面放到 y = 0**。页面要用的唯一一个尺寸是
   `DIM.hd = 1.1418`——台面到脚底，`main.js` 用它把机器立在地板上。
4. **把盖子合上再导出**。原始文件里盖子是支在 67° 的，那让模型变成一个 10×10×10 的立方体，
   构图很差，而且没给页面留下任何可揭示的东西。现在合盖是一个**状态**：开机那一秒半它自己抬起来，
   之后归你（`F`，或走带台那个圆钮）。抬盖的角度是从玻璃法线量出来的 67.11°，不是写死的。

   铰链线**不是**写死的，是从 `立方体.011` 上读出来的——盖子的旋转节点，它的局部 X 就是铰链轴
   （在世界里正好是 +X，这才叫一条横贯左右的线而不是角上的一根销），原点就是线上一点。
   而绕自己的轴转不会移动自己的原点，所以开盖合盖两种姿态读出来是同一条线。

   这条线曾经是我猜的 `(0, 5.30, 台面)`，比真值低了 0.33。**绕一条偏低的轴合盖，整块盖板会下沉
   0.54 单位——19 mm**：盖子陷进底座，而平衡锤本来在真闭合下有 5 mm 余量，于是从玻璃里穿出来。
   两个症状一个根因，都在导出时按毫米报出来（`lid_underside_mm` / `clearance_mm`），
   因为那是肉眼开始能看见的尺度。

   **还有一步的顺序很要命**：开盖必须在**重新挂父级之前**做。文件里"开盖"就是 `立方体.011`
   旋转归零；一旦它被挂到 `Cover` 空物体下，它的 `rotation_euler` 就是相对新父级量的，
   而那个父级的 `matrix_parent_inverse` 是按旧关系烘的——再写零得到的是一个任意姿态，不是开盖。
   放错位置的那一版，所有报告都正常，只有 `cover_open_deg` 悄悄变成 0.13°：盖子合着、位置也对，
   但页面拿到的行程只有 0.13°，永远打不开。所以脚本现在**先开盖、再量角度、最后合盖**，
   而文件被保存成什么姿态都不影响结果。

5. **把唱头翻正。** `立方体.004`（`ArmCartridge`）在 `.blend` 里是**里外翻转**的：它的多边形绕序和文件里其他所有网格相反。
   判定它的就是**有符号体积为负**——行列式是正的、整条父级链上没有任何镜像，那么唯一能让体积变负的就是绕序。

   后果是看得见的。three 靠绕序判断三角形的哪一面是正面，所以它当成"正面"画出来的是唱头的**内壁**——
   盒子远处那面墙盖在了近处那面之上。光照也是错的，因为 Blender 从绕序推导法线，那些法线同样朝内。

   导出时反转面循环，两件事一起解决（这里有一处报错：`rep["winding_flipped"]`）。
   判断是**通用的**而不是写死名字，所以将来再出现第二个会被抓住而不是发出去。这一步在内存里做，
   `.blend` 是作者的东西，这个脚本从不写它。

脚本里有两处不写下来就会再踩一次的坑，注释里写了：`matrix_parent_inverse` 只补偿新父物体的世界矩阵，
不会重算子物体相对旧父物体的局部矩阵（于是敞开的防尘盖会瞬间摊平）；以及三个空物体的名字会和网格撞名。

导出结果是 `assets/turntable.glb`：48 个节点、41 个网格、23 个材质、**0 张贴图**，1.29 MB。
这个文件留着，是模型的源产物；页面用的是编进 bundle 的那一份。

### 材质

GLB 里那 23 个材质是纯色，没有一张贴图。页面**不直接用它们**，而是用导出时起的名字
（`Plinth` / `Brass` / `Vinyl` / `RecordLabel` / `CoverAcrylic` …）换成自己的一套
`MeshPhysicalMaterial`。这么做的原因是：只有页面自己的材质才能被环境探针、主题过渡和幽灵渐变碰到——
磁带版的 `cas.materials` 就是干这个的。

有三个物体在 `.blend` 里**根本没有材质**（唱针、压住它的夹片、平衡锤上的环）。Blender 不在乎，
视口给它们一块中性灰；glTF 对没有材质的图元给的是**默认白色** —— 那会正落在唱臂最尖端，
成为画面里最亮的东西。所以这三个按节点名兜底（`MAT_FALLBACK`），不是猜的。

#### 防尘盖是真的玻璃

唯一一个走物理的材质。`transmission: 1` + 真实 IOR 1.49（亚克力），带 `dispersion` 色散，
**没有吸收**。**它每帧多渲一整遍场景**——这正是磁带版的烟熏窗和这版盖子最初都把它省掉的原因，
也是 `floor.js` 手写平面反射而不用 `Reflector` 插件的原因：那个插件挂 `onBeforeRender`，
而它在**透射这一遍里会再响一次**，于是渲染中途重入 `setRenderTarget`。见 `floor.js` 开头。

`thickness` 是这里唯一不字面的地方，得说明白：盖子是个**薄壁壳**（690 顶点，网格体积只有包围盒的
4.4%），壁厚实打实只有 0.4 mm —— 你在边缘看到的 49 mm 是裙边，几何本身就有。透过 0.4 mm 的板折射
几乎等于不折射，所以 `thickness` 填的是一个**等效光程**：0.30 局部单位约合 11 mm 玻璃。这比真实
防尘盖的板材厚、比壳的深度薄得多，是让边缘读起来像有体积的块、而不是一张染色膜的那个值。
**它是关于壁厚的假话，不是关于光学的。**

其余都是亚克力的真数：`ior` 1.49；`dispersion` 0.65——three 按
`halfSpread = (ior - 1) * 0.025 * dispersion` 展开成 1.482..1.498，正好是亚克力在可见光下实测的
折射率跨度。边缘那圈彩色条纹就是"这是块实心玻璃"这个判断的主要来源。

**没有 `attenuation`，这是刻意的。** 一开始我给了它一个偏绿的吸收色（真亚克力的边是绿的），
结果整块玻璃发绿。原因是 `volumeAttenuation` 把颜色**取幂**：路径上是常数 `thickness`，
于是它把红光从**所有**透射光里均匀扣掉，而不是只扣路径长的地方。真实玻璃的绿在**边**上——
你要透过 50 mm 才看得见——而 three 表达不了那个，因为整块网格只有一个 `thickness`。
所以诚实的做法是干脆不要这个染色，而不是把一个均匀的色偏放在物理本该放渐变的地方。
边上该有的绿改由 `dispersion` 给，它是几何相关的，因为它作用在折射本身之上。

两个渲染上的坑，都是量出来的不是猜的：

- **透射分辨率必须满分辨率。** 半分辨率下透过盖子看到的一切都被双三次采样糊掉，而"糊"在玻璃后面
  读起来是**磨砂**不是**厚**——那是玻璃块和一张描图纸的区别。
- **地面镜像那一遍不能要真折射。** three 的透射缓冲是**按相机**建的，所以镜像会自己再要一遍完整的
  场景渲染。而镜像是 0.6 分辨率、隔帧、再过 13 抽模糊的，分不出真假。所以镜像那一遍盖子换成
  `glassFlat` 平替（`useCheapGlass`）。不换的话页面会掉到 0.8 档，而那一档第一个被牺牲的就是镜像
  本身——等于用关掉地面反射来换正确的玻璃。

#### 唱片的沟槽和各向异性

沟槽原来是一张**法线贴图**（170 条同心正弦脊）。它被删掉了，因为它会**摩尔纹**：
170 条脊摊在 1024 的图上，在屏幕上每条纹只有约三个像素。采样比像素网格更密的东西不会平均掉，
它会**干涉**——盘面长出一朵跟着转盘一起转的玫瑰。

替代品是黑胶**本来就是**的东西：**各向异性**。微观结构沿沟槽排列，所以高光沿沟槽拉伸。
它是表面属性、不是贴图上的图案：不采样、不混叠、任何距离都成立。
`roughnessMap` 保留（光滑径向渐变，没有环，打不了拍）。

顺带一提**为什么顶面要重投影 UV**（`planarCapUV`）：Blender 默认的圆柱展开把端面摊成 uv 方块
左右两个小圆、侧壁摊成中间一条带——对铁罐是好展开，对唱片完全不对。唱片上所有"从中心量半径"
画出来的图案（那道粗糙度渐变、标签的印刷图）透过那种排布采样出来都不是同心圆，是一圈**放射状的
辐条**，而且辐条跟着转盘一起转。重投影成平面投影之后它们才是对的；顶面以外推到图案之外，
**而那个"推出去"只对没有各向异性的材质安全**——见下。

**方向必须来自逐顶点 `tangent` 属性，不能来自 UV。** 网格没有切线时，three 用 **UV 的屏幕空间导数**
推导它；那个导数是**逐三角形恒定**的，于是各向异性方向也逐三角形恒定——在 128 段的扇形上就是
每 3° 一条硬边，渲染出来是一个**带折痕的风车**。而**平滑顶点法线救不了它，因为法线从来不是被切成
一片片的那个东西**。真正的 `tangent` 属性会逐片元插值，风车就消失了。

两个弯路，都记在代码注释里：把 UV 改成极坐标**治不了**（TBN 本身仍是逐三角形的），而且它会
**悄悄弄坏 `roughnessMap`**——那是一张按平面投影画的径向渐变，用极坐标采样会读成一条直线带。
另外，给顶点"停靠"一个常数 UV（`planarCapUV` 对付侧壁的老办法）在**各向异性下是致命的**：
UV 导数为零 → 零切线帧 → Smith 可见性项除以它的分量 → 得到 **Inf**，而 Inf 能活过 bloom，
把大半个画面染黑，**控制台一句话都不说**。

#### 全场的灯光有一个总增益

`lights.js` 的 `GAIN`。五盏灯是**互相配平**的，那个配平才是要保住的东西，所以调电平是在表上加一个
增益，而不是去改十二个强度值——后者会让配平在改动里悄悄跑掉。它同时乘到探针面板上
（`buildRigPanels`），这是把它放在那里的意义：那些面板**就是**灯箱，环境反射是从它们身上拍的。
一套只把自己调暗、不把反射调暗的灯，会让黄铜从一个方向被照亮、从另一个方向被反射。
`main.js` 把同一个增益乘到 `scene.environmentIntensity` 上——在这个场景里环境是光源，不是背景板。

实测（同机位 A/B，`GAIN` 1.0 → 0.75）：台面模型 **−21.5%**、底座立面 −15.1%，
而**背景 0.0%**——背景是 `scene.background` 的渐变，不受灯照，这是对的。

## 音乐

唱片里装的是 **Matryoshka — Sacred Play Secret Place**（专辑 *Laideronnette*）。
源文件是 24bit/192kHz 的 FLAC（187 MB），已转成 44.1kHz / VBR ~169 kbps 的 MP3（6.4 MB），
放在 `assets/sacred-play-secret-place.mp3`。

**这个仓库里不含那首歌**：它是 Matryoshka 的商业录音，不再分发（`.gitignore` 里只忽略
`assets/` 下的音频扩展名，模型 `assets/turntable.glb` 是照常提交的）。
克隆下来想让它出声，把任意音频丢成 `assets/sacred-play-secret-place.mp3` 就行；
或者点页头的 **ADD MUSIC**（或按 `O`，或把音频文件拖到页面上）装一首自己的。
完全没有音频时页面会走「音频加载失败 · 仅转盘动画」那条降级路径，转盘照转、唱臂照落，只是没有声音。

### 换片是「刻」出来的，不是切过去的

磁带版里换一首是那支写头在标签上扫一遍；唱片版对应的是**刻纹**。

新的印刷先画在一张与标签同形状的副本上，悬在原标签上方半毫米，再由一个**从中心轴向外张开的遮罩**
放进来；等遮罩走到标签边缘，唱片自己的贴图才正式接手。所以整个过程读起来是一次连续的刻，
而不是一次溶解或一次硬切。同时有一圈暖色的光环跟着遮罩边缘走，走到底之后停住、再过一会儿自己暗掉——
印刷比光先完成，光在同一帧消失就成了一次「切断」。

遮罩不是每帧重画的渐变，而是一张软边圆盘贴图**绕着圆心缩放**：一次 uniform 写入，
换成每帧画一遍就是每帧一次贴图上传。

这里有两个只有踩过才知道的地方，都写进 `textures.js` 的注释了：

* three 的 `alphamap_fragment` 取的是 `texture2D(alphaMap, uv).g`——**绿通道，不是 alpha**。
  把遮罩写进 `.a` 而让 rgb 保持白色，读数就恒等于 1，遮罩等于不存在，第一次张开就是全开。
* three 的 uv 变换是 `uv * repeat + offset`，而遮罩要的是「采样坐标随 k 变小而往外走」，
  所以是 `repeat = 1/k`、`offset = 0.5 - 0.5/k`。写成 `repeat = k`（直觉上那个）
  会把标签半径乘上 k，于是 k = 0.5 时遮罩已经全开了。

### 换掉出厂曲目

把新文件丢进 `assets/`，改 `src/main.js` 顶部的 `TRACK`（`title / artist / album / src`），
然后双击 `重建.bat`。曲名会自动写到唱片的纸标签上。

放完一首会自动抬臂回位、再落针重放（`REW_SECONDS = 8.5`，计数器变铜色）。

## 走带的模型

一张唱片的每一面 = 唱针从外圈走到内圈的一趟，所以这台机器做的一切都是「针尖在哪」的函数。
模型里唯一真正的状态是 `progress`（0 = 外圈，1 = 标签），转盘的转角、轴承的角度、
计数器全都从它推出来。这是磁带版 `areaL` 的思路留了下来，只是把两个带盘换成了一个坐标。

唱臂的角度不是调出来的，是算出来的：枢轴、主轴、针尖围成一个三角形，两条固定边是
`d = 5.921`（枢轴到主轴）和 `AE = 6.492`（枢轴到针尖），于是**针尖的半径就是轴承的角度**——
`armAngle(r)` 就是余弦定理反过来读。循迹因此是半径上的一次插值，而整个行程
从停放柱到内圈只有 46°。

转盘的转角：外部有时钟时（`<audio>` 的 `currentTime`）它就是 `progress` 的函数，所以拖滑轨
唱片会落在音乐所在的位置；没有外部时钟时它是一个累加器，停下来那一下还有一个
按 `exp(-2.1 t)` 衰减的自转——一块这么重的转盘要一两秒才停，在按下按钮的那一帧冻住，
是让一台机器看起来像视频的最快办法。

## 界面

沿用了原页面那几条决定，因为它们都还是对的：

* **一份档案 = 一张纸**。所有用文字说的东西都印在同一块半透明纸上，挂在右侧三分之一处。
  纸自己带着那段落差（`margin-left: var(--retract)`），而不是让里面的字各走各的——
  折叠、滚轮推近、「细节特写」三种收法走的是同一个数。
* **一个旋钮：根字号**。界面上每个长度都是根字号的倍数，根字号是 `clamp(16px, 1.1111vw, 21px)`：
  **1440 下正好 16px，2560 下是 21px**，纸、字、控制台、发丝线一起长 1.31 倍。
  `border` 与 `outline` 刻意留在 px：发丝线在任何缩放下都是一个设备像素。
* **一套状态，处处一样**。hover 永远是铜色，press 永远是下沉 1px，focus 永远是同一道铜色发丝线加偏移。
* **底部控制台**是 `1fr auto 1fr`：两侧等宽，中间的翻页块落在画幅自己的中线上。

幽灵不是换成一块灰料，而是靠动画材质自己的 uniform 渐变过去的（颜色、粗糙度、金属度、清漆、
法线强度一起走到目标值，不透明度最后下去）。渐变用的材质副本**每个 mesh 一份**——
原件是共享的，改一个就会改一片——副本第一次用时克隆一次，之后每帧只改 uniform，
不触发任何 shader 重编译。

### 截图

`tools/shots.mjs` 是**一次加载、连拍多张**：等 loader 清一次，然后按一串步骤——
每步在页面里 eval 一段 JS（通常就是点页面自己的按钮）、等一会儿、抓一张。
`page-shot.mjs` 每张都会重新加载页面，在这台机器上代价是整个 bundle 加整个 GLB 再解析一遍，
所以批量看图用前者。

```bash
# 先起一个开着 CDP 的 Edge：
#   msedge --headless=new --remote-debugging-port=9445 --use-angle=d3d11 \
#          --ignore-gpu-blocklist --user-data-dir=%TEMP%\x about:blank
node tools/shots.mjs "file:///D:/.../index.html" out "@tools/shots.2k.json" 2560 1440 1
```

`--use-angle=swiftshader` **不要加**。软件渲染下这页 boot 要 114 秒（幽灵材质的预编译要对
六条档案各渲一遍），有 GPU 时是 2–3 秒。

`tools/check-transport.json` 是一个回归检查：按播放，然后每 80 ms 记一次
`[时刻, 滑轨位置, audioEl.paused, currentTime]`。它要证明的是**声音在针落到唱片上之后才起**——
日志里应该能看到前 ~0.64 s 全是 `paused = true, currentTime = 0.00`。

`tools/_px2rem.mjs` 是把 `styles.css` 从 px 换成 rem 的一次性 codemod，留着当文档。

## 已知遗留

**自适应画质只降不升。** `watchPerf` 的 `qualityCeil` 一旦被某个 2.5 秒窗口压下去，本会话就
回不来了（`quality < qualityCeil` 才允许回升）。设计意图是"记住被证明过慢的档位"，但**加载后的
沉降期不是证据**：`loop()` 一启动就是首帧分配透射缓冲（满分辨率半浮点 4×MSAA，约 120 MB）、
后处理链按最终尺寸建 target、首帧才链接的着色器——而 `dt` 被钳在 50 ms，所以这些帧全读作 50 ms，
2.5 秒就够触发。实测在一台完全不忙的机器上出现过 `170 fps · js 1.01 ms · dpr×0.8 · no-mirror`。
现在 `PERF_SETTLE_MS`（4 秒墙钟）内的窗口被丢弃，但**只降不升**这条本身没动——真要改属于另一个决定。

`src/textures.js` 里还留着磁带版的贴图代码（`tapeMaps`、`tapeEdgeTexture`、`labelTexture`
及其水彩绘制那一大段、`matTexture`、`deckDecalTexture`），**现在都没有引用**。
它们不影响产物——esbuild 会把没人用的函数摇掉——但确实是可以删的。之所以留着，
是因为删 `labelTexture` 要连带删掉它那一整套水彩辅助函数，而那次改动和「让页面跑起来」无关。
要清就先 grep 确认没有引用再删。

**`grooveNormal` 现在也没人用了**（唱片的沟槽法线贴图已换成各向异性，见「材质」一节）。
它和上面那批不同：不是磁带时代的遗留，是这一版刚废弃的，而且它**生成一张 1024² 的贴图**——
启动时白算一次。删它是安全的，`grep grooveNormal` 只剩 `textures.js` 自己的定义。
